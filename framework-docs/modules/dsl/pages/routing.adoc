= Routing
:description: Routing patterns available in the Pipelite DSL

Pipelite supports three routing types, accessible via the `.toRoute()` method of the DSL.

== Content-Based Router

The *Content-Based Router* routes the message to one of the flows listed in the routing table based on content.

[source,java]
----
.toRoute(route -> route.contentBased()               // <1>
    .when(new PayloadTypeCondition(OrderEvent.class), // <2>
          "order-processing-flow")
    .when(new ExpressionCondition("${header.type} == 'PAYMENT'"),
          "payment-flow")
    .otherwise("default-flow")                        // <3>
    .build()
)
----
<1> Selects content-based mode.
<2> Each `.when(condition, flowName)` adds an entry to the routing table.
<3> `.otherwise` defines the fallback flow if no condition is satisfied.

=== Available conditions

[cols="1,3"]
|===
|Class |Description

|`PayloadTypeCondition`
|Checks that the payload is an instance of the specified type.

|`ExpressionCondition`
|Evaluates a textual expression (see xref:expressions.adoc[Expressions]).
|===

To create custom conditions, implement the `Condition` interface:

[source,java]
----
public interface Condition {
    boolean evaluate(IOContext exchange);
}
----

== Recipient List

The *Recipient List* pattern sends the message to *multiple flows* simultaneously.

[source,java]
----
.toRoute(route -> route.dynamic()
    .toRecipientList(list -> {
        list.addRecipient("flow-a");
        list.addRecipient("flow-b");
        return list;
    })
)
----

NOTE: The `toRecipientList` API via `ProcessOperations` is deprecated.
Prefer the variant via `toRoute(route -> route.dynamic())`.

== Routing Slip

The *Routing Slip* dynamically specifies the sequence of flows to traverse.
The list of destinations is read from the `routing-slip` property of the `Exchange`.

[source,java]
----
.toRoute(route -> route.dynamic()
    .routingSlip()
)
----

Setting the routing slip on the Exchange:

[source,java]
----
exchange.setRoutingSlip(RoutingSlip.of("flow-a", "flow-b", "flow-c"));
----

The framework processes the flows in the specified order, using the `RoutingSlipRouterNode`.

== Return Address

The *Return Address* pattern routes the response to the flow indicated in the `return-address` header.

[source,java]
----
// Set by the caller before sending the message
exchange.setReturnAddress("reply-handler-flow");
----

The `ReturnAddressRouterNode` reads the header and routes the Exchange to the corresponding flow in the registry.
