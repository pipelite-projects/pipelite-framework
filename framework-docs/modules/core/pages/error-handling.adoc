= Error Handling
:description: Error management, retry channel, and flow execution dump in Pipelite

Pipelite offers two error handling modes at the flow level: the *retry channel* and the *custom error channel*.
Both are configured via the DSL at the end of the flow definition.

== Retry Channel

The retry channel is the simplest mode.
When an exception propagates through the flow, the framework serializes the `Exchange` into a `FlowExecutionDump` and re-queues it for a subsequent attempt.

[source,java]
----
FlowDefinition flow = Pipelite.defineFlow("resilient-flow")
    .fromSource("kafka://my-topic")
    .process("parse", exchange -> {
        // may throw exceptions
    })
    .toSink("slf4j://output")
    .withRetryChannel()    // <1>
    .build();
----
<1> Enables automatic retry with the default strategy.

When an attempt fails, execution resumes from the point of failure, not from the flow's source. See xref:internals:error-handling-internals.adoc[Error Handling Internals] for how this is implemented.

== Custom Error Channel

For more flexible error handling, use `withErrorChannel`:

[source,java]
----
FlowDefinition flow = Pipelite.defineFlow("flow-with-error-channel")
    .fromSource("http://api/v1/ingest")
    .process("process", exchange -> { /* ... */ })
    .toSink("slf4j://output")
    .withErrorChannel(builder ->
        builder.toSink("slf4j://error-log")   // <1>
               .build()
    )
    .build();
----
<1> The error channel sends the error message to the configured sink.

`ErrorChannelOperations` exposes:

[source,java]
----
builder.toSink(String url)   // destination for the error message
       .build()              // produces ErrorChannelDefinition
----

== Default handler

If no error channel is configured, the exception is handled by `GlobalDefaultExceptionHandler`, which logs the error and stops processing without propagating the exception to the caller.

== Custom error-handling strategies

Neither the retry channel nor a custom error channel fit every case. To implement a completely custom error-handling strategy (e.g. forwarding to an external alerting system), see xref:extensibility:exception-handling-spi.adoc[Exception Handling SPI].
