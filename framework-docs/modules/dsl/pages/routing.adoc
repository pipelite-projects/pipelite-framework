= Routing
:description: Routing patterns available in the Pipelite DSL

A flow can end by handing its `Exchange` on to other flows or channels chosen at runtime, instead of
a fixed `toSink(...)`. Two constructs do this: `toRoute(...)`, which picks destinations with
expressions, and `toRecipientList(...)`, which sends it to a fixed set of destinations.

== Expression-based routing

`toRoute(...)` evaluates a list of expressions in order and sends the message to the destinations of
the *first* one that is true.

[source,java]
----
.toRoute(route -> route.dynamic()
    .when("Headers['type'] == 'PAYMENT'").then("queue://payment-flow")               // <1>
    .when("Headers['type'] == 'REFUND'").then("queue://refund-flow", "slf4j://audit") // <2>
    .otherwise("queue://default-flow")                                                // <3>
    .end()                                                                            // <4>
)
----
<1> `.when(expression)` is a boolean expression (see xref:expressions.adoc[Expressions]) and `.then(...)` the destination reached when it is true.
<2> `.then(...)` accepts several destinations: the message is sent to all of them, each receiving its own `Exchange`: the headers are copied, the payload is the same object (see xref:core:messages.adoc#_what_is_copied_and_what_is_shared[What is copied, and what is shared]).
<3> `.otherwise(...)` is the fallback when no expression is true, and it is optional. Without it, a message that matches nothing fails like a failed step, and is handled by the flow's error handling.
<4> `.end()` closes the routing table.

A destination is a URL: `queue://<queue name>` reaches an internal flow (the queue its `fromSource("queue://...")` reads), any other channel adapter protocol reaches an external system. A bare name is rejected when the flow is defined.

=== Destinations computed per message

A destination may contain a `#{...}` expression, evaluated against each message with `Payload` and `Headers` available:

[source,java]
----
.toRoute(route -> route.dynamic()
    .when("Payload != null").then("queue://#{Headers['region']}-orders")
    .end()
)
----

NOTE: `#{...}` is resolved for each message when it is routed. The `${...}` property placeholders of the Spring integration are *not* resolved in routing destinations - see xref:spring-integration:endpoint-url-properties.adoc[Endpoint URL Property Placeholders].

== Recipient List

The *Recipient List* pattern sends the message to a *fixed set of destinations*, all of them, every time:

[source,java]
----
.toRecipientList("queue://flow-a", "queue://flow-b", "slf4j://audit-logger")
----

Each recipient is a URL and receives a copy of the `Exchange` (see xref:core:messages.adoc#_what_is_copied_and_what_is_shared[What is copied, and what is shared]). The flow ends there, as with `toRoute(...)`. A recipient list needs at least one recipient, and every recipient must be a URL: a mistake is reported when the flow is defined.

It does not look at the message. When the destinations depend on it, use `toRoute(...)` above: it picks the destinations of the first expression that is true, and can send to several of them (pass them all to `.then(...)`).
