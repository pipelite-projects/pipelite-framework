= Testing API Reference
:description: Complete reference for Preconditions, Actions, and Expectations in pipelite-test-support

Full reference for all factory methods exposed by `PipeliteTest` (accessible via `import static io.pipelite.test.PipeliteTest.*`).

== Preconditions

Preconditions configure the fixture before execution.
They are passed to `given(Precondition...)` and applied in order.

[cols="2,4"]
|===
|Method |Description

|`header(String name, Object value)`
|Adds a header to the initial exchange.

|`inputPayload(Object payload)`
|Sets the input payload of the initial exchange.

|`flowDefinition(FlowDefinition flow)`
|Registers a flow to be deployed in the test context.
Multiple flows can be chained via `link://` between them.

|`flowConfiguration(Class<?> configClass)`
|Scans a `@FlowConfiguration` class (no-arg constructor) and registers all discovered flow definitions.

|`flowConfiguration(Class<?> configClass, Object... dependencies)`
|Same as above, but injects the given objects into the configuration class by runtime type,
following the plain-Java SPI dependency-resolution contract.

|`timeout(long seconds)`
|Overrides the default capture timeout (5 s) used by `supplyTo(...)`.
Reduce when testing flows that stop or filter before reaching their sink.
Must be a positive value.
|===

== Actions

Actions activate the component under test.
They are passed to `when(Action)`.

[cols="2,4"]
|===
|Method |Description

|`process(Processor processor)`
|Executes the `Processor` lambda synchronously against the prepared exchange.
No runtime, no endpoints.
Returns `ThenOperations` immediately.

|`supplyTo(String entryPointEndpoint)`
|Starts a `DefaultPipeliteContext` with all registered flows, injects the exchange
into `entryPointEndpoint`, and waits (up to the configured timeout) for the exchange
to reach its sink.
Automatically redirects the real terminal sink to an internal `test://` capture adapter.
`link://` hops between chained flows are left untouched.
Returns `ThenOperations` after the context stops.
|===

=== Flow exception handling

If a processor throws a `RuntimeException` during `supplyTo(...)`, the fixture does not
silently time out.
Instead it throws `AssertionError` with the original exception as the cause:

[source]
----
AssertionError: Flow execution failed with an unhandled exception: <message>
    Caused by: java.lang.RuntimeException: <message>
----

To handle exceptions inside the flow, set an `ExceptionHandler` on the `FlowDefinition`:

[source,java]
----
FlowDefinition flow = Pipelite.defineFlow("my-flow")
    .fromSource("in")
    .process("risky", (io, c) -> { /* ... */ })
    .withExceptionHandler((ex, exchange) -> {
        exchange.setOutputPayload("fallback");
    })
    .toSink("out")
    .build();
----

== Expectations

Expectations are verifications evaluated by `then(Expectation...)`.
They are passed as varargs; all are evaluated in order.

=== Processor-mode expectations

These require a `TestProcessContribution`, available only after `process(...)`.
Using them in flow mode (after `supplyTo(...)`) throws `AssertionError` with a clear message.

[cols="2,4"]
|===
|Method |Description

|`isSuccess()`
|Asserts the processor completed without throwing.

|`isFailure()`
|Asserts the processor threw a `RuntimeException`.

|`isExecutionStopped()`
|Asserts the processor called `contribution.stopExecution()`.

|`failureCause(Throwable expected)`
|Asserts the failure cause is exactly `expected` (reference equality).
|===

=== Flow-mode expectations

[cols="2,4"]
|===
|Method |Description

|`isExecutionCompleted()`
|Asserts the flow reached its sink before the configured timeout.

|`isNotExecutionCompleted()`
|Asserts the flow did *not* reach its sink (e.g. was filtered or stopped).
|===

=== Exchange-level expectations

These apply to both modes.

[cols="2,4"]
|===
|Method |Description

|`payloadEquals(Object expected)`
|Asserts the effective payload equals `expected` (null-safe `Objects.equals`).
The effective payload is the output payload if set, otherwise the input payload.

|`hasHeader(String name)`
|Asserts the named header is present.

|`headerEquals(String name, Object expectedValue)`
|Asserts the named header is present and equal to `expectedValue`.

|`noHeader(String name)`
|Asserts the named header is absent.

|`payloadAs(Class<T> type, Consumer<T> assertions)`
|Asserts the payload is of type `T` and passes the typed instance to `assertions`.
Use this to plug AssertJ or JUnit assertions on individual fields of a complex payload:

[source,java]
----
.then(payloadAs(OrderDto.class, order -> {
    assertThat(order.getTotal()).isEqualByComparingTo(BigDecimal.valueOf(99.99));
    assertThat(order.getStatus()).isEqualTo("CONFIRMED");
}));
----
|===

=== Step and output grouping

[cols="2,4"]
|===
|Method |Description

|`output(Expectation... expectations)`
|Groups expectations that apply to the *final* exchange.
Semantically equivalent to passing them directly to `then(...)`, but makes the target explicit
when mixed with `step(...)` in the same call.
Requires at least one expectation.

|`step(String stepName, Expectation... expectations)`
|Verifies `expectations` against the exchange snapshot captured right after the named step executed.
Throws `AssertionError` if the step was never reached, or if the name is ambiguous across
multiple registered flows (see disambiguation below).

|`step(String flowName, String stepName, Expectation... expectations)`
|Same as above but pins the lookup to `flowName`.
Use when two registered flows share a step name:

[source,java]
----
.then(
    step("flow-a", "transform", payloadEquals("A")),
    step("flow-b", "transform", payloadEquals("B")));
----
|===

== Custom expectations

Any lambda matching `(Exchange exchange, TestProcessContribution contribution) -> void` is a valid `Expectation`:

[source,java]
----
.then((exchange, contribution) -> {
    String payload = (String) exchange.getInputPayload();
    if (!payload.startsWith("OK:")) {
        throw new AssertionError("Expected payload to start with 'OK:', got: " + payload);
    }
});
----

`contribution` is `null` in flow mode; check before accessing it.

== ThenOperations — direct payload/header access

In addition to `then(...)`, `ThenOperations` exposes extraction methods for when an assertion library requires direct access to the value:

[cols="2,4"]
|===
|Method |Description

|`getOutputPayload()`
|Returns the effective payload (output if set, otherwise input).
Throws `IllegalStateException` if called before `when(...)`.

|`getOutputPayloadAs(Class<T> expectedType)`
|Returns the effective payload cast to `expectedType`.
Throws `ClassCastException` if the cast fails.

|`getHeaderAs(String name, Class<T> expectedType)`
|Returns the header value cast to `expectedType`, or `null` if absent.
|===

Example using AssertJ directly:

[source,java]
----
ThenOperations result = given(inputPayload(42))
    .when(process((io, c) -> io.setOutputPayload(io.getInputPayloadAs(Integer.class) * 2)))
    .then(isSuccess());

assertThat(result.getOutputPayloadAs(Integer.class)).isEqualTo(84);
----

== Multi-flow testing

Register multiple flows and chain them via `link://`:

[source,java]
----
FlowDefinition flowA = Pipelite.defineFlow("flow-a")
    .fromSource("entry")
    .process("step-a", (io, c) -> io.setOutputPayload("from-a"))
    .toSink("link://next-entry")
    .build();

FlowDefinition flowB = Pipelite.defineFlow("flow-b")
    .fromSource("next-entry")
    .process("step-b", (io, c) -> io.setOutputPayload(
        io.getInputPayloadAs(String.class) + "-enriched"))
    .toSink("out")
    .build();

given(
        flowDefinition(flowA),
        flowDefinition(flowB),
        inputPayload("start"))
    .when(supplyTo("entry"))
    .then(
        output(isExecutionCompleted(), payloadEquals("from-a-enriched")),
        step("flow-a", "step-a", payloadEquals("from-a")),
        step("flow-b", "step-b", payloadEquals("from-a-enriched")));
----

== Testing with `@FlowConfiguration`

If your flows are declared via the xref:spring-integration:index.adoc[Spring Boot integration] SPI, use `flowConfiguration(...)` instead of `flowDefinition(...)`:

[source,java]
----
class OrderFlowConfiguration {

    @DefineFlow
    public FlowDefinition orderFlow(OrderService orderService) {
        return Pipelite.defineFlow("order-flow")
            .fromSource("orders-in")
            .process("process", (io, c) -> orderService.process(io.getInputPayloadAs(Order.class)))
            .toSink("orders-out")
            .build();
    }
}

// In the test:
OrderService mockService = new MockOrderService();

given(
        flowConfiguration(OrderFlowConfiguration.class, mockService),
        inputPayload(new Order("ORD-001")))
    .when(supplyTo("orders-in"))
    .then(isExecutionCompleted());
----

Dependencies are resolved by runtime type; pass one instance per parameter type used in `@DefineFlow` methods.
