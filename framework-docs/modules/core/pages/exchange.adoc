= Exchange
:description: The Exchange object as the message transport container in Pipelite

The `Exchange` is the fundamental vehicle through which data travels along a flow.
Each time a source produces an event, a new `Exchange` is created and passed through all nodes in the pipeline. It carries an input payload, an optional output payload, and a set of xref:messages.adoc[Headers].

== Payload access

[source,java]
----
// Read the incoming payload
Object raw = exchange.getInputPayload();
MyDto dto  = exchange.getInputPayloadAs(MyDto.class);

// Check the payload type
Class<?> type = exchange.getInputPayloadType();

// Set the output payload
exchange.setOutputPayload(result);
----

NOTE: If a processing step never calls `setOutputPayload(...)`, the framework automatically forwards the input payload to the output before handing the `Exchange` to the next node — a step that only inspects or validates the payload, without transforming it, does not need to copy it manually.

== Headers

`Exchange` exposes convenience methods (`putHeader`, `tryGetHeader`, `expectHeader`, `tryGetHeaderAs`, `removeHeader`) that delegate to the underlying `Headers` object. See xref:messages.adoc[Message and Headers] for the complete `Headers` API reference.

== Return Address

The *Return Address* pattern allows the flow to reply to a dynamically specified channel.

[source,java]
----
exchange.setReturnAddress("reply-flow");
Optional<String> replyTo = exchange.tryGetReturnAddress();
exchange.resetReturnAddress();
----

== Routing Slip

The *Routing Slip* pattern allows the sequence of flows to traverse to be specified dynamically.

[source,java]
----
exchange.setRoutingSlip(routingSlip);
Optional<RoutingSlip> slip = exchange.tryGetRoutingSlip();
----
