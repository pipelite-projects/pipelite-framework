= Espressioni
:description: Sintassi del motore di espressioni di Pipelite per filter e routing condizionale

Il modulo `pipelite-expression` fornisce un motore di valutazione di espressioni testuali usato da `filter` e `ExpressionCondition`.

== Sintassi

Le espressioni sono stringhe Java valutate a runtime.
Il placeholder centrale è `${body}`, che si riferisce al payload corrente dell'Exchange.

=== Placeholder disponibili

[cols="1,3"]
|===
|Placeholder |Risolve

|`${body}`
|Il payload di input dell'`Exchange` (equivalente a `exchange.getInputPayload()`)

|`${header.<name>}`
|Il valore dell'header con il nome specificato
|===

=== Esempi di espressioni

[source]
----
// Filtraggio: continua solo se il body non è null
${body} != null

// Filtraggio su stringa non vuota
${body} != null && !${body}.isEmpty()

// Routing condizionale su header
${header.type} == 'ORDER'

// Confronto numerico
${header.priority} > 5
----

== Utilizzo nel DSL

=== Nel filter

[source,java]
----
.filter("only-valid", "${body} != null && !${body}.isEmpty()")
----

Il nodo `ExpressionFilterNode` valuta l'espressione su ogni `Exchange`.
Se la valutazione restituisce `false`, l'elaborazione del messaggio si interrompe.

=== Nell'ExpressionCondition

[source,java]
----
.toRoute(route -> route.contentBased()
    .when(new ExpressionCondition("${header.type} == 'PAYMENT'"), "payment-flow")
    .otherwise("default-flow")
    .build()
)
----

== Implementazione

Il motore di espressioni è implementato in `TextExpressionEvaluator` (modulo `pipelite-core`).
Risolve i placeholder sull'`ExpressionVariables` popolato a partire dall'`Exchange` corrente.

L'`ExpressionUtils` (package `io.pipelite.core.support.expression`) fornisce metodi helper per la valutazione programmatica delle espressioni.

NOTE: Il motore di espressioni è volutamente semplice.
Per logiche condizionali complesse è preferibile usare un `Processor` con logica Java standard.
