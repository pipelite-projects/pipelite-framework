= HTTP Channel Adapter
:description: Undertow-based HTTP adapter for inbound and outbound communication

The `http-channel-adapter` module implements an inbound HTTP server based on *Undertow 2.2.x*.

== Dependency

[source,xml,subs="attributes+"]
----
<dependency>
    <groupId>{project-group-id}</groupId>
    <artifactId>http-channel-adapter</artifactId>
    <version>{project-version}</version>
</dependency>
----

== Usage as source (inbound)

[source,java]
----
Pipelite.defineFlow("http-inbound")
    .fromSource("http://ingress")     // <1>
    .process("handle", exchange -> {
        String body = exchange.getInputPayloadAs(String.class);
        exchange.setOutputPayload("OK");
    })
    .toSink("slf4j://log")
    .build();
----
<1> Opens an HTTP listener on port 8080 (default) at path `/ingress`.

=== URL format

[source]
----
http://<path>
----

[cols="1,1,3"]
|===
|Parameter |Default |Description

|path
|(required)
|The HTTP path on which the server listens (e.g. `/api/v1/events`)
|===

The Undertow server is started automatically by `HttpChannelAdapter.onContextStarted()` upon the first registration of an HTTP consumer.

=== Adapter-wide configuration

Port, host and the maximum size of a single request body are shared by every `http://` source in
a context - one Undertow instance serves all of them - so they are configured once, adapter-wide,
the same way Kafka's `bootstrapServers` is:

[source,java]
----
context.addChannelConfigurer((HttpChannelConfigurer) configuration -> {
    configuration.setPort(8443);
    configuration.setHost("127.0.0.1");
    configuration.setMaxEntitySize(1024 * 1024); // bytes
});
----

[cols="1,1,3"]
|===
|Setting |Default |Description

|port
|8080
|The Undertow listener's TCP port.

|host
|`0.0.0.0`
|The interface Undertow binds to.

|maxEntitySize
|10 MiB
|Upper bound on a single request's body size, in bytes. A request exceeding it receives a `413`
response instead of being read into memory unbounded.
|===

WARNING: `HttpChannelAdapter` has no built-in authentication and does not terminate TLS - it is
not safe to expose directly on an untrusted network. Put a reverse proxy (nginx, an API gateway,
a load balancer) in front of it to handle TLS termination and authentication before traffic
reaches this adapter.

== Usage as sink (outbound)

The module includes an `HttpProducer` for sending messages to external HTTP endpoints.

[source,java]
----
.toSink("http://target-service/api/notify")
----

The `HttpProducer` sends the payload as the body of an HTTP POST request.

== Multiple path registration

Multiple paths can be registered on the same server:

[source,java]
----
context.registerFlowDefinition(
    Pipelite.defineFlow("flow-orders")
        .fromSource("http://orders").toSink("slf4j://orders").build()
);
context.registerFlowDefinition(
    Pipelite.defineFlow("flow-payments")
        .fromSource("http://payments").toSink("slf4j://payments").build()
);
----

`HttpChannelAdapter` maintains a per-path consumer map and shares a single Undertow instance.

WARNING: Registering two flows on the same HTTP path is not allowed: `IllegalStateException` will be thrown.
