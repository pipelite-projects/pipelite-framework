= Routing
:description: Pattern di routing disponibili nel DSL di Pipelite

Pipelite supporta tre tipologie di routing, accessibili tramite il metodo `.toRoute()` del DSL.

== Content-Based Router

Il *Content-Based Router* instrada il messaggio verso uno dei flow elencati nella routing table in base al contenuto.

[source,java]
----
.toRoute(route -> route.contentBased()               // <1>
    .when(new PayloadTypeCondition(OrderEvent.class), // <2>
          "order-processing-flow")
    .when(new ExpressionCondition("${header.type} == 'PAYMENT'"),
          "payment-flow")
    .otherwise("default-flow")                        // <3>
    .build()
)
----
<1> Seleziona la modalità content-based.
<2> Ogni `.when(condition, flowName)` aggiunge una voce alla routing table.
<3> `.otherwise` definisce il flow di fallback se nessuna condizione è soddisfatta.

=== Condizioni disponibili

[cols="1,3"]
|===
|Classe |Descrizione

|`PayloadTypeCondition`
|Verifica che il payload sia istanza del tipo specificato.

|`ExpressionCondition`
|Valuta un'espressione testuale (vedi xref:expressions.adoc[Espressioni]).
|===

Per creare condizioni personalizzate implementa l'interfaccia `Condition`:

[source,java]
----
public interface Condition {
    boolean evaluate(IOContext exchange);
}
----

== Recipient List

Il pattern *Recipient List* invia il messaggio a *più flow* contemporaneamente.

[source,java]
----
.toRoute(route -> route.dynamic()
    .toRecipientList(list -> {
        list.addRecipient("flow-a");
        list.addRecipient("flow-b");
        return list;
    })
)
----

NOTE: L'API `toRecipientList` tramite `ProcessOperations` è deprecata.
Preferire la variante tramite `toRoute(route -> route.dynamic())`.

== Routing Slip

Il *Routing Slip* specifica dinamicamente la sequenza di flow da attraversare.
La lista di destinazioni viene letta dalla property `routing-slip` dell'`Exchange`.

[source,java]
----
.toRoute(route -> route.dynamic()
    .routingSlip()
)
----

Impostazione del routing slip sull'Exchange:

[source,java]
----
exchange.setRoutingSlip(RoutingSlip.of("flow-a", "flow-b", "flow-c"));
----

Il framework elabora i flow nell'ordine indicato, usando il `RoutingSlipRouterNode`.

== Return Address

Il pattern *Return Address* instrada la risposta verso il flow indicato nell'header `return-address`.

[source,java]
----
// Impostato dal chiamante prima di inviare il messaggio
exchange.setReturnAddress("reply-handler-flow");
----

Il `ReturnAddressRouterNode` legge l'header e instrada l'Exchange verso il flow corrispondente nel registry.
