= Message and Headers
:description: The Message as payload container and the Headers API

== Message

The `Message` (package `io.pipelite.spi.flow.exchange`) is the container for the application payload.
Each `Exchange` has an input `Message` and, optionally, an output `Message`.

=== Main API

[source,java]
----
Message input = exchange.getInput();

// Payload access
Object payload       = input.getPayloadAs(Object.class);
MyDto dto            = input.getPayloadAs(MyDto.class);
Class<?> payloadType = input.getPayloadType();
boolean hasPayload   = input.hasPayload();
----

To produce a new payload inside a processor, use `exchange.setOutputPayload(...)` — see xref:exchange.adoc[Exchange].

=== SimpleMessage

The concrete implementation is `SimpleMessage`, which carries a typed payload and a map of message-own headers.
Default values are created internally by the context's `MessageFactory`.

== Headers

The `Headers` class (interface and implementation `HeadersImpl`) provides access to message metadata.

=== Read

[source,java]
----
Headers headers = exchange.getHeaders();

// Optional read
Optional<String> value = headers.tryGetHeader("x-request-id");

// Read with expectation (throws NoSuchElementException if absent)
String value = headers.expectHeader("x-request-id");

// Typed read
Optional<Integer> n = headers.tryGetHeaderAs("retry-count", Integer.class);

// Presence check
boolean present = headers.hasHeader("x-request-id");
----

=== Write

[source,java]
----
headers.putHeader("x-correlation-id", "xyz-789");
headers.removeHeader("x-temp");
----

=== Reserved headers

The framework reserves a small number of header and property names for its own routing mechanisms — Return Address and Routing Slip (see xref:exchange.adoc[Exchange]). Use the dedicated `Exchange` methods (`setReturnAddress`, `setRoutingSlip`, and their `tryGet*` counterparts) rather than reading or writing these directly.

WARNING: Avoid choosing application header names that could collide with framework-reserved ones.
