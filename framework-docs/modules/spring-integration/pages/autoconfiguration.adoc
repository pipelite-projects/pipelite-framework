= Autoconfiguration
:description: How Pipelite autoconfiguration works with Spring Boot

== Dependency

[source,xml,subs="attributes+"]
----
<dependency>
    <groupId>{project-group-id}</groupId>
    <artifactId>pipelite-spring-starter</artifactId>
    <version>{project-version}</version>
</dependency>
----

== @EnablePipelite

The `@EnablePipelite` annotation activates the entire Pipelite infrastructure in the Spring context.
It must be applied to a configuration class:

[source,java]
----
@Configuration
@EnablePipelite
public class PipeliteConfig {

    @Bean
    public FlowDefinition myFlow() {
        return Pipelite.defineFlow("my-flow")
            .fromSource("time://tick?period=10000")
            .toSink("slf4j://log")
            .build();
    }
}
----

With `@SpringBootApplication`, it can be placed directly on the main class:

[source,java]
----
@SpringBootApplication
@EnablePipelite
public class Application {
    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
----

== Auto-configured components

`@EnablePipelite` imports `PipeliteConfigurationImportSelector`, which registers:

[cols="1,3"]
|===
|Bean |Responsibility

|`PipeliteContext`
|The framework singleton context, built by `PipeliteAutoConfiguration`.

|`FlowDefinitionRegistrar`
|`BeanPostProcessor` that intercepts every bean of type `FlowDefinition` and registers it in the `PipeliteContext`.

|`PipeliteContextInitializer`
|Initializes the context with internal factories.

|`PipeliteContextLifecycleManager`
|Implements `SmartLifecycle` to start and stop the context in sync with Spring.
|===

== Lifecycle with Spring

`PipeliteContextLifecycleManager` integrates with the Spring lifecycle:

* `start()` → invoked by Spring after the `ApplicationContext` refresh.
* `stop()` → invoked by Spring during orderly shutdown.

The precedence order ensures that all `FlowDefinition` beans have already been registered before the context starts.

== Registering multiple FlowDefinitions

All beans of type `FlowDefinition` are automatically detected and registered by `FlowDefinitionRegistrar`:

[source,java]
----
@Configuration
@EnablePipelite
public class FlowConfig {

    @Bean
    public FlowDefinition orderFlow() {
        return Pipelite.defineFlow("order-flow")
            .fromSource("kafka://orders")
            .toSink("slf4j://orders")
            .build();
    }

    @Bean
    public FlowDefinition paymentFlow() {
        return Pipelite.defineFlow("payment-flow")
            .fromSource("kafka://payments")
            .toSink("slf4j://payments")
            .build();
    }
}
----

Manual registration in the `PipeliteContext` is not required.
