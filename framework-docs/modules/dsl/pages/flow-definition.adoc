= Flow Definition
:description: Complete DSL reference for defining a Pipelite pipeline

== Entry point

[source,java]
----
FlowDefinitionBuilder builder = Pipelite.defineFlow("flow-name");
----

The flow name must be unique within the `PipeliteContext`.

== fromSource

Defines the source endpoint of the flow.
A source is always a URL, with the scheme of a channel adapter.

[source,java]
----
.fromSource("time://ticker?period=1000")
.fromSource("http://ingress")
.fromSource("kafka://my-topic")
.fromSource("queue://order-processing")
----

`queue://` is the queue in front of an internal flow: the receiving end of a xref:channel-adapters:queue.adoc[`queue://`] hop. Its name must be unique within the `PipeliteContext`, since `queue://order-processing` is read by exactly one flow: `start()` fails if two flows declare the same one. A bare name with no scheme, such as `.fromSource("order-processing")`, is not a source and is rejected when the flow is defined.

A queue source can also declare `?concurrency=N` to have `N` consumers of the queue process up to `N` messages at the same time instead of one at a time:

[source,java]
----
.fromSource("queue://order-processing?concurrency=4")
----

Every concurrent source shares one framework-owned worker pool (default 200 threads, override via `ConfigurablePipeliteContext.setMaxSourceWorkerPoolSize(int)`) instead of getting dedicated threads of its own — total thread usage stays bounded regardless of how many flows declare `concurrency`. It is rejected at startup on any source that is not a queue (`http://`, `file://`, `kafka://`, `time://`, ...).

== process

Adds a generic processing node.

[source,java]
----
.process("step-name", (exchange, contribution) -> {
    String input = exchange.getInputPayloadAs(String.class);
    exchange.setOutputPayload(input.trim());
})
----

The second argument is a `Processor` (functional interface) - it receives the `Exchange` and a
`ProcessContribution`, which most processors ignore (it exists for the rare case one needs to call
`stopExecution()` and end the flow early from inside the processor).
The name (`"step-name"`) is used for logging and tracing.

== transformPayload

Pure payload transformation, without direct access to the `Exchange`.

[source,java]
----
.transformPayload("to-dto", payload ->
    objectMapper.convertValue(payload.getPayloadAs(Map.class), MyDto.class)
)
----

== filter

Stops the flow if the expression evaluates to `false`.
See xref:expressions.adoc[Expressions] for the syntax.

[source,java]
----
.filter("non-empty", "${body} != null")
----

== wireTap

Sends a copy of the message to a secondary endpoint without blocking the flow.

[source,java]
----
.wireTap("audit", "slf4j://audit-logger")
----

== split

Splits a collection payload into independent messages, processes each one through a dedicated segment of steps, and aggregates the results back into a single message before the flow continues.
See xref:split-aggregate.adoc[Split / Aggregate] for complete documentation.

[source,java]
----
.split("split-items", segment -> segment
    .process("step-1", processor)
    .end())
----

== toSink

Defines the destination endpoint of the flow.
After `toSink`, only `withRetry`, `withErrorChannel`, `withExceptionHandler`, and `build` are available.

[source,java]
----
.toSink("slf4j://output")
.toSink("kafka://output-topic")
.toSink("queue://next-flow")
----

A sink is always a URL: the protocol of a channel adapter, or `queue://<name>` to hand the Exchange to the flow that reads that queue (see xref:channel-adapters:queue.adoc[`queue://`]). A bare name such as `.toSink("output")` is rejected when the flow is defined.

A flow does not need a sink. Leave `toSink` out and the flow simply ends after its last step; a flow that ends with `toRoute` or `toRecipientList` hands the Exchange on through them.

== toRoute

Adds a routing node.
See xref:routing.adoc[Routing] for complete documentation.

[source,java]
----
.toRoute(route -> route.contentBased()
    .when(new PayloadTypeCondition(OrderEvent.class), "queue://order-flow")
    .otherwise("queue://default-flow")
    .build()
)
----

== withRetry

Enables automatic retry on exception, resuming the flow at the step that failed rather than
replaying it from the source. Available after `toSink` or as an alternative termination after a
processor - mutually exclusive with `withErrorChannel`/`withExceptionHandler`.

An exhaustion action is mandatory: the lambda only type-checks once it ends in
`onErrorChannel(...)` or `onExceptionHandler(...)`.

[source,java]
----
.withRetry(retry -> retry
    .maxAttempts(3)
    .backoff(Backoff.exponential(Duration.ofSeconds(2)))
    .onErrorChannel(err -> err.toDLQ()))
.build()
----

`maxAttempts` and `backoff` are both optional. See xref:core:error-handling.adoc[Error Handling]
for the full reference, including `Backoff.linear`/`Backoff.exponential` and `onExceptionHandler`.

== withErrorChannel

Configures a custom error channel - a single hand-off with no retry attempts, unlike the
`onErrorChannel(...)` that `withRetry` uses as its own exhaustion action, which reaches the same
target only after attempts are exhausted.

[source,java]
----
.withErrorChannel(err -> err.toChannel("queue://dead-letter"))
.build()
----

The target is a URL, like every destination in the DSL: `queue://<name>` for an internal flow, or a
registered channel adapter's protocol (`kafka://...`) for an external system. `err.toDLQ()` targets
the framework's built-in dead letter queue instead, with no flow to write.

== withExceptionHandler

Hands the exception straight to a user-supplied `ExceptionHandler`, with no dump, no retry, and no
routing of any kind.

[source,java]
----
.withExceptionHandler((exception, exchange) -> {
    // fully custom handling
})
.build()
----

== build

Finalizes the definition and returns an immutable `FlowDefinition`.

[source,java]
----
FlowDefinition definition = Pipelite.defineFlow("my-flow")
    .fromSource("time://tick")
    .toSink("slf4j://log")
    .build();
----

NOTE: `build()` does not start the flow.
The flow is activated only after `PipeliteContext.start()`.
